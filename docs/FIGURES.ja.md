# 図はどこから来たか

*[English](FIGURES.en.md)*

`docs/figures/` の12枚のPNGと、各READMEに貼っている `docs/example-dashboard.*.png` は、このリポジトリで唯一「コマンド1本で再生成できないもの」です。ここでは**どの図がどのチャートなのか**を明記します。1枚だけ差し替えるときに迷わないためです。

**同じ6枚が言語ごとに2組あります。** `docs/figures/en/` と `docs/figures/ja/` です。チャートは描画する文字列をすべてページのペイロードから受け取るので、軸ラベル・凡例・見出しの言語は `--lang` で決まります。英語版の文書は英語版の図を参照しています。クラブ名は連盟の表記そのままで、どちらの組でも翻訳していません。

**どれもプロット用ライブラリでは描いていません。** このプロジェクトのグラフはすべて、ページ自身のJSONペイロードからブラウザ上でSVGとして組み立てています（`togakuren/trends.py` と `togakuren/dashboard.py` の `svg()` ヘルパー）。依存パッケージがゼロなのはこのためです。PNGはその要素のスクリーンショットです。

## 作り直す手順

```bash
togakuren trends --lang ja --club 430 --out /tmp/trends.html
togakuren dashboard --lang ja --privacy aggregate --out /tmp/dashboard.html
```

dashboard 側の `--privacy aggregate` は省略できません。選手単位の表示がすべて落ちるので、コミットされる画像に写り込みうるものが最初から描画されません。

そのうえで、ここが一度失敗した箇所です。

**暗い配色で撮ること。** ページは `prefers-color-scheme` に従い、ヘッドレスブラウザはライトを返します。一方でコミットされている図はすべて暗い配色です。そのまま撮ると、暗い配色向けの文字色が白地に乗ります。`fig-promotion.png` が軸の説明を読めない状態で公開されていたのはこれが原因です。撮る前に `dashboard.CSS` のダーク側の値を `:root` に流し込んで配色を固定し、**結果を目で確認してください。**

対象の要素は、兄弟要素を `body` まで遡って隠すことで切り出します。要素自身に `display` を強制してはいけません。`#radars` はCSSグリッドなので、`display:block` を当てると12枚のレーダーが1枚に潰れます。周囲の背景を切り落としたら、**必ず256色に減色します**。

```bash
pngquant --force --output docs/figures/ja/fig-bubbles.png 256 raw.png
```

これは見た目の問題ではありません。フラットな配色のグラフなので256色でも見分けがつかず、サイズは約60%減ります。**PNGは差分圧縮が効かない**ので、コミットした図は版ごとに丸ごと履歴に残ります。

## 図を変更するときの2つのルール

**絵そのものが変わったときだけ撮り直す。** 文書側のラベルの言い回しを直すのは撮り直す理由になりませんし、自分が編集していない方の言語も撮り直す理由になりません。2つの組は独立したファイルです。以前この作業で、7ファイルなのに履歴に13ブロブ・1.2MBが残り、うち234KBは既に削除済みのファイルの分でした（これは永久に回収できません）。

**寸法を変えない。** 各文書はGitHubの表示幅で読める前提で今の幅に合わせてあります。現状は564〜1122pxです。

## なぜ自動化していないか

ヘッドレスブラウザを使えばCIで再現できるようになり、それは実際に有効な改善です。まだやっていません。ただしそれは、年に2回変わるかどうかの12枚の画像のために、テストマトリクスへブラウザのダウンロードを持ち込むことでもあります。**このプロジェクトの主眼は標準ライブラリだけで動くこと**なので、その原則を優先しました。この判断にはコストがあり、後から発見されるより書いておくべきなので、この文書があります。
