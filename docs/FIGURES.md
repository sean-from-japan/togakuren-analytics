# Where the figures come from

*[日本語版](FIGURES.ja.md)*

The six PNGs in `docs/figures/` are the only things in this repository that
cannot be regenerated by a single command, so this document says exactly what
each one is a picture of.

None of them is drawn by a plotting library. Every chart in this project is an
SVG built in the browser from the page's own JSON payload — see the `svg()`
helpers in `togakuren/trends.py` and `togakuren/dashboard.py` — which is why the
project has no dependencies. The PNGs are screenshots of those elements.

## What each file is

| file | page | element | chart |
|---|---|---|---|
| `fig-conversion.png` | `trends` | `#conv-line` | Conversion by division, season by season |
| `fig-grades.png` | `trends` | `#grades` | Year groups: share of minutes against goals per 90 |
| `fig-promotion.png` | `trends` | `#moves` | Points per game either side of a division change |
| `fig-trajectory.png` | `trends` | `#trajectory` | One club's path across seasons |
| `fig-bubbles.png` | `dashboard` | `#bubbles` | League position against shot volume |
| `fig-fingerprints.png` | `dashboard` | `#radars` | Every club's six indices, side by side |

## Regenerating one

```bash
togakuren trends    --out /tmp/trends.html      # or
togakuren dashboard --out /tmp/dashboard.html
```

Open the page, let the charts render, and export the single element named above
— any browser's developer tools will copy a node's rendered SVG, and the
screenshot path works too. Then **quantise to 256 colours**:

```bash
pngquant --force --output docs/figures/fig-bubbles.png 256 raw.png
```

That step is not cosmetic. These charts are flat colour, so 256 colours is
visually identical and roughly 60% smaller — 441 KB became 169 KB across the
set. PNGs do not delta-compress, so every version of a figure that is ever
committed stays in the history at full size.

## Two rules for changing a figure

**Only re-shoot when the picture changes.** Rewording a label in the document is
not a reason to replace the image. An earlier round of this project left 13
blobs and 1.2 MB in the history for 7 files, 234 KB of it belonging to files that
had already been deleted and will never be reclaimed.

**Keep the dimensions.** The documents rely on the existing widths reading
sensibly at GitHub's content width; the sizes now in the tree are 606–1104 px
across.

## Why this is not automated

A headless browser would make these reproducible in CI, and that is a real
improvement that has not been made. It would also mean a browser download in the
test matrix for six images that change perhaps twice a year, in a project whose
whole point is that it runs on the standard library and nothing else. The
trade-off was decided in favour of the dependency-free rule, and this document
exists because that decision has a cost that should be written down rather than
discovered later.
