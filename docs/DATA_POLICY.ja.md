# データの取り扱い方針

*[English](DATA_POLICY.md)*

このデータセットに登場するのはプロではなく、アマチュアの学生です。このツールが何を集め、何を公開させないようにしているか、そしてなぜ既定値をそう置いたかを記録しておきます。

## 情報源

東京都大学サッカー連盟は、日程・結果・メンバー表・試合記録を [f-togakuren.com](https://www.f-togakuren.com/match) で公開しています。サイトはVueのシングルページアプリケーションで、各ページは `data.f-togakuren.com` 上のCockpit CMSから描画されており、そのための読み取りトークンはサイト自身が `common.js` で全ブラウザに配っています。

このツールはトークンをハードコードせず、ブラウザと同じようにサイトのJavaScriptから読み取ります。要求するのはサイトがすでに描画している内容だけで、リクエスト間にはスリープを入れ、すべてのレスポンスをキャッシュするので再実行はゼロコストです。`robots.txt` が禁じているのは `/wp-admin/` のみで、プライバシーポリシーにも公開ページの閲覧を制限する記述はありません。利用規約のページはそもそも存在しません。

ただしそれは、**中身を自由に再配布してよい**ということではありません。以下がその話です。

## このリポジトリに収集データは入っていない

試合記録もメンバー表もエクスポート結果もコミットしていません。入っているのはコード、架空の名前で作ったテスト用データ、そしてこの方針だけです。`data/` と `reports/` は `.gitignore` に入っています。

これはスクレイピング用ライブラリの通常のやり方でもあります。[soccerdata][sd] も [worldfootballR][wf] も抽出コードを配布し、集めたデータは利用者の手元に置きます。同時に、次に書く問題を避けられる唯一のやり方でもあります。

[sd]: https://github.com/probberechts/soccerdata
[wf]: https://github.com/JaseZiv/worldfootballR

## 線を引くのは取得ではなく再配布

個人情報保護法のもとでは、誰かが先に公開したからといって情報が個人情報でなくなるわけではありません。氏名・生年月日・身長・出身校は、連盟のサイトにあろうとGitHub上のCSVにあろうと特定の個人を識別します。それを第三者に提供することは規制されており（27条）、原則として本人の同意が必要です。

統計情報は別です。個人情報保護委員会自身の見解として、複数人の情報を集計して特定の個人との対応関係を排したものは個人情報に該当せず、法の適用範囲外です。

- [統計情報と匿名加工情報の違いは何ですか](https://www.ppc.go.jp/all_faq_index/faq1-q15-2/)
- [統計情報としてB社に提供した場合、B社においては個人情報に該当しますか](https://www.ppc.go.jp/all_faq_index/faq1-q1-17/)

したがってこのツールが強制している実務上のルールは次のとおりです。

| 出す先 | 入れてよいもの |
|---|---|
| ローカルのデータベースとレポート | すべて。公開物の個人的な分析にあたる |
| 公開するもの | 集団の集計値、または残存リスクを明示した仮名の選手行 |
| このリポジトリ | コードのみ |

これは法的助言ではなく、設計上の制約です。

## イニシャル化は匿名化ではない

山田 太郎を `山.太.` に置き換えると守っているように感じますが、ほとんど守れていません。メンバー表は公開されており、部は12チームで、分析に必要な列——チーム、ポジション、出場数——それ自体が識別子として働きます。

`privacy-check` はこれを仮定せず実測します。2026年の1部、270分以上出場した189人の場合:

| 準識別子 | k | 一意になる行 |
|---|---|---|
| チーム | 13 | 189件中0件 (0%) |
| チーム + ポジション | 1 | 189件中17件 (9%) |
| チーム + ポジション + 出場数 | 1 | 189件中105件 (56%) |
| チーム + ポジション + 出場数 + 得点 | 1 | 189件中146件 (77%) |

`k = 1` は、その列の組み合わせで一意になる行が少なくとも1つあるという意味です。つまり名前の列が何に置き換わっていようと、連盟自身のメンバー表を使えば特定の人物に戻せます。表の半分以上が、ごく普通の分析用の3列だけで一意に定まります。

自分の抽出結果で確かめられます。

```bash
python3 -m togakuren privacy-check --series "2026 1部"
```

## ツール側の対応

- `--privacy full` はローカルのレポートの既定値で、`--public` を付けたものには使えません。
- `--privacy initials` は存在しますが、`--public` では同じく拒否されます。多くの人が最初に手を伸ばす選択肢なので用意はしてあり、上の表がその実際の効果なので拒否しています。
- `--privacy pseudonym` は名前をソルト付きの非可逆なラベルに置き換えます。ソルトを渡さなければ実行ごとに新しく生成します。この方式で作ったレポートには、チームとポジションだけで何行が一意のままかを明記したバナーが入るので、残存リスクがファイルと一緒に移動します。
- `--privacy aggregate` は選手単位の行を一切出しません。その出力が、上の意味での統計情報にあたります。
- `ingest --drop-personal-data` は読み込み後に氏名・カナ・メンバー表の詳細・監督名を削除し、不透明なIDだけを残します。このツールの指標はすべてその後も動作し、テストがそれを保証しています。

選手単位の出力が実際にどう見えるかは [PLAYER_ANALYSIS_SAMPLE.ja.md](PLAYER_ANALYSIS_SAMPLE.ja.md) にあります。中身は架空のシーズンで、実在の人物は含まれていません。

## リクエスト間隔と取り下げ

リクエストの既定間隔は0.5秒で、レスポンスはディスクにキャッシュされるので、5シーズン分のフルバックフィルでも数百リクエストが一度きりです。この間隔を外さないでください。

連盟、または結果が掲載されているクラブがこのツールの存在を望まないのであれば、issueを立ててもらえれば取り下げます。迷惑をかけてまで続ける価値のあるものではありません。
